# MCP 入门：什么是 MCP，为什么需要它

> 来源：mcp-for-beginners Module 0 — Introduction
> 整理时间：2026-06-03

---

## 一句话总结

**MCP 是一个开放的标准协议，让 AI 模型能统一的方式跟外部工具、API、数据源交互。**

---

## 1. 为什么需要 MCP？

### 没有 MCP 之前

每个 AI 应用跟工具集成时，都要写一堆定制代码：

```
AI 模型 A + 数据库 X → 写一套代码
AI 模型 A + 搜索引擎 Y → 再写一套
AI 模型 B + 数据库 X → 又写一套
```

问题：
- 每个模型跟每个工具的组合都要单独对接
- 每个厂商的 API 格式不一样
- 工具多了维护成本指数级增长
- 换模型或换工具都要重写

### MCP 解决什么

就像 **USB-C 统一了设备接口**，MCP 统一了 AI 跟工具的接口：

- 同一个工具只需要实现一次 MCP Server
- 任何支持 MCP 的 AI 应用都能用这个工具
- 换模型、加工具都不用改代码

> **跟我们的项目什么关系**：我们现在 `execute_sql` 是直接写死在 Agent 循环里的函数调用。如果用 MCP 包装，`execute_sql` 就变成一个标准化工具，以后多个 Agent 都能复用，不需要每个 Agent 写一套连接逻辑。

---

## 2. MCP 核心概念

### 三大角色

| 角色 | 干什么 | 类比 |
|------|--------|------|
| **MCP Host** | 运行 AI 模型的应用（Claude Desktop、VS Code、IDE） | 手机 |
| **MCP Client** | 跟 Server 建立 1:1 连接，负责通信 | 手机的 USB 口 |
| **MCP Server** | 提供具体能力的小程序（工具、数据、提示词） | U 盘 |

Host 里面可以有多个 Client，每个 Client 连一个 Server。一个 Host 可以同时连多个 Server。

### Server 提供的三种东西

| 概念 | 是什么 | 例子 |
|------|--------|------|
| **Tools** | 可执行的函数，AI 能调用来"做事情" | 查数据库、发邮件、计算 |
| **Resources** | 数据源，给 AI 提供上下文信息 | 文件内容、API 返回数据 |
| **Prompts** | 预定义的提示词模板 | 代码审查模板、翻译模板 |

> **跟我们的项目关系**：`execute_sql` 就是一个 **Tool**。表结构信息（Students/Courses/Enrollments）可以做成 **Resource**。System Prompt 可以做成 **Prompt** 模板。

### 协议架构（两层）

```
┌─────────────────────────┐
│  数据层（JSON-RPC 2.0）   │  ← 消息格式：请求/响应/通知
│  生命周期 + 能力发现      │
├─────────────────────────┤
│  传输层                  │  ← 怎么传数据
│  - STDIO（本地进程）      │    本地用 STDIO
│  - Streamable HTTP（远程）│    远程用 HTTP + SSE
└─────────────────────────┘
```

> **我们会用 STDIO**：Agent 和 MCP Server 都在同一台机器上，通过进程通信，不走网络。

## 3. MCP 的请求流程

```
用户输入 "北京今天天气怎么样"
      │
      ▼
┌──────────┐     ┌───────────┐     ┌──────────────┐
│ MCP Host │────→│ AI Model  │────→│ MCP Server   │
│ (客户端)  │←────│ (Claude)  │←────│ (天气工具)    │
└──────────┘     └───────────┘     └──────────────┘
    │                  │                    │
    │  1. 用户提问      │                    │
    │  2. Model 决定    │                    │
    │     调用天气工具   │                    │
    │                  │  3. Host 调 Server  │
    │                  │     天气 API        │
    │                  │  4. 返回天气数据     │
    │  5. Model 生成    │                    │
    │     自然语言回复   │                    │
    │  6. 展示给用户     │                    │
```

这个流程跟我们 Agent 循环完全一样，区别只是中间隔了一个 MCP 协议层。

## 4. MCP 实际好处

| 好处 | 说明 |
|------|------|
| **互操作性** | 不同厂商的 AI 模型共用同一套工具 |
| **一致性** | 所有工具调用走同一个协议，行为可预测 |
| **复用性** | 工具写一次，各个项目都能用 |
| **减少幻觉** | 外部真实数据源比模型自己编靠谱 |
| **隐私** | 敏感数据留在本地 Server，不用塞 prompt 里 |

---

## 5. 关键认知

1. **MCP 就是一个标准化的接口**，没有魔法。它规定"工具长什么样、怎么调、怎么返回"，就像 HTTP 规定了网页怎么传
2. **MCP 跟我们已经写的 Tool Calling 不冲突**。我们现在手动写 JSON Schema + 函数调用，MCP 是把这层标准化、可复用
3. **对我们 Step 2 的目标**：把 `execute_sql` 包装成 MCP Server，然后 Agent 通过 MCP Client 调用它。代码结构变了，但本质逻辑不变
4. **MCP 不是 Anthropic 独家的**，虽然它最初是 Anthropic 推的，但现在已经是社区标准，有 C#、Java、Python、TS、Rust 等多语言 SDK
